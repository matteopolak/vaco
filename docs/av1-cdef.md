# AV1 constrained directional enhancement

`vaco-codec-av1::cdef` implements AV1 specification §7.15 direction search,
primary/secondary filtering, variance adjustment, and damping for 8-, 10-, and
12-bit samples. Frame syntax retains all strength entries, including the valid
single-entry table signalled with `cdef_bits = 0`.

## How it works

Direction search measures the eight line partitions of each 8x8 luma block.
Luma variance adjusts primary strength; chroma reuses the luma direction with
the specified subsampling mapping and one less damping bit. Filtering reads an
immutable two-pixel neighborhood. Primary and secondary taps use constrained
differences, signed rounding, and neighborhood clipping.

The frame pass skips an 8x8 region only when all four 4x4 mode-info cells have
`skip` set, or its 64x64 strength index is absent. Neighbor samples remain
available across tile boundaries; the padded mode-info frame boundary controls
availability, as specified by `is_inside_filter_region()`. Filtered samples
never become another block's input.

## How to change it

Change `src/cdef.rs` for arithmetic and neighborhood behavior,
`src/frame_header.rs` for CDEF header syntax, and `src/decode.rs` for index
selection and frame application. Preserve the distinction between disabled
CDEF and an enabled single-entry table. Preserve immutable source samples when
changing buffering or parallelism.

The checked-in oracle is generated by `scripts/gen-av1-cdef-oracle.py` from
the pinned BSD-2-Clause dav1d C implementation. It compiles the original scalar
function bodies in temporary storage with a small compatibility prelude. The
Rust implementation follows the published specification; no dav1d code is
included in production Rust.

```sh
python3 scripts/gen-av1-cdef-oracle.py crates/tool/vaco-checkasm/tests/fixtures/av1-cdef-dav1d.bin
CARGO_INCREMENTAL=0 cargo test -p vaco-checkasm --test av1_cdef --target-dir <private-target>
```

The differential covers 7,680 cases: every direction, primary strength,
secondary strength, and luma/chroma damping at all three sample precisions, with
4x4/4x8/8x8 geometry and all sixteen frame-edge masks. It compares the searched
direction, variance, and every output sample. This is scalar conformance
evidence; there is no separate SIMD CDEF implementation yet.

Measured on 2026-09-04: all 7,680 cases agree exactly, including nonzero low
bits in 10/12-bit samples. That covers 286,720 active output samples plus each
case's direction and variance. The five frame/header regressions pass; the
zero-bit-index test first reproduced the old `-1` versus expected `0` failure.
The AV1 crate suite passes 35 tests with its existing busy-frame oracle ignored.
AV1 all-target and focused checkasm Clippy checks pass with warnings denied.

## Configuration

No environment variables. `cdef_params()` supplies damping and strength
tables; `read_cdef()` supplies each 64x64 unit's table index. Sequence bit depth
and chroma subsampling determine scaling and block geometry. Decoder `Budget`
accounts for the temporary frame buffer.

## Dependencies and verification boundary

Production depends on `vaco-core`, reconstruction planes, frame-header syntax,
and the persisted mode-info grid. Oracle regeneration requires Python, network
access to the pinned dav1d file, and a C compiler; tests use the checked-in
binary fixture without network access.

This kernel does not establish full AV1 frame conformance. The Argon corpus is
not acquired in this repository, the decoder registry entry remains disabled,
and inter prediction and other in-loop stages have independent gaps. Issue
#340 remains open until its Argon frame-profile acceptance is reachable and
measured.
